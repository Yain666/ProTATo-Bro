# Weapon / Combat Design

## 目的
- 这份文档用于记录武器系统、子弹行为、战斗侧扩展方案。
- 用途：沉淀远程武器、子弹类型、爆炸弹、命中特效等设计结论。
- 目标：即使上下文压缩或切换对话，也能直接恢复武器战斗侧的实现计划。

## 当前已落地结论
- 普通直射武器继续走通用 `bullet.prefab`。
- `Bullet.cs` 负责普通投射物的通用生命周期、移动、碰撞、穿透、弹射、命中特效。
- 子弹外观不再靠 prefab 一把武器一份，而是由武器数据驱动：
  - `projectile_sprite_path`
  - `projectile_scale_x`
  - `projectile_scale_y`
  - `projectile_collider_width`
  - `projectile_collider_height`
- 武器本体世界图也允许按数据驱动缩放：
  - `sprite_scale_x`
  - `sprite_scale_y`
- 武器音效按行为事件拆配置，当前预留：
  - `fire_sfx_path`
  - `impact_sfx_path`
  - `explosion_sfx_path`
- 当前已落地约定：
  - 文件名带“发射”的音效用于武器发射
  - 近战统一随机使用 `近战攻击1/2/3`
  - 火炮类爆炸继续使用 `Boom`
- 当前碰撞方案统一使用 `BoxCollider2D`，并允许临时发光轮廓辅助调参。
- 枪口闪本轮已经移除，仅保留命中特效。
- 小火炮当前由 `id = 205` 作为第一把爆炸武器样板。
- 小火炮原始素材当前放在 `Assets/AI/WeaponCannon/`，运行时正式加载前仍需转入 `Assets/Resources/Weapons/...` 对应目录。
- 武器配置，包括测试用小火炮，也必须先改 `WeaponData.xlsx`，再转出 `WeaponData.json`，不保留“只手改 Json”的链路。
- 小火炮第一版链路已落地：图标、世界图、子弹图、4 帧爆炸序列帧均已接入 `Resources`。
- 爆炸范围圆环仅作为调参辅助保留在代码里，默认关闭，不作为正式运行时表现。
- 第二把爆炸武器样板已接入：`id = 206` 的重型火炮，当前复用同一套爆炸序列帧资源，主差异在数值、子弹尺寸、飞行速度和爆炸半径。

## 爆炸弹方案总目标
- 不把爆炸逻辑继续硬塞进通用 `Bullet.cs`。
- 以“普通子弹”和“爆炸子弹”两条行为链拆分实现。
- 先用“小火炮”做第一把爆炸武器样板，再扩展到“重型火炮”或其他 AoE 武器。

## 设计原则
- 行为按类型拆分，外观尽量数据驱动。
- 普通直射弹与爆炸弹共享已有武器生成链路，但各自维护独立行为脚本。
- 能复用已有伤害链路就不另起一套，爆炸伤害仍走 `DamageUtil.ResolveDamage`。
- 不为了少写一个脚本，把普通弹、爆炸弹、持续区域伤害、分裂弹全部揉进同一个大类。
- 第一阶段只做最小可用爆炸弹，不顺手扩成一整套复杂弹药框架。

## 拆分方案

### 1. 普通子弹链
- 继续使用：
  - `Assets/Resources/Weapons/Projectiles/bullet.prefab`
  - `Assets/Script/Weapon/Bullet.cs`
- 负责：
  - 直线移动
  - 命中单体
  - 穿透
  - 弹射
  - 命中特效
- 不负责：
  - 爆炸范围判定
  - 爆炸特效生命周期
  - 落点 AoE 伤害

### 2. 爆炸子弹链
- 新增独立行为：`ExplosiveBullet.cs`
- 新增独立 prefab：`explosive_bullet.prefab`
- 负责：
  - 飞行阶段
  - 命中或到达寿命末端时触发爆炸
  - 爆炸范围检索
  - 对范围内目标逐个结算伤害
  - 播放爆炸特效后回收

## 爆炸弹完整计划

### Phase 1：最小可用版本
- 目标：先让小火炮打得出去、炸得开、伤害结算正确。
- 范围：
  - 子弹飞行
  - 命中即爆炸
  - 圆形范围检测
  - 对爆炸范围内怪物逐个伤害结算
  - 基础爆炸特效或占位反馈
- 暂不做：
  - 复杂抛物线
  - 多段爆炸
  - 燃烧地面
  - 爆炸击退的复杂调参
  - 墙体/地形阻挡细则

### Phase 2：数据字段补齐
- 为爆炸武器补充专用配置字段，优先放进 `WeaponConfigData`，并经 `WeaponRuntimeFactory` 转到运行时。
- 计划字段：
  - `projectile_behavior_type`
  - `explosion_radius`
  - `explosion_damage_multiplier`
  - `explosion_vfx_path`
  - `explosion_hit_limit`（可选）
- 其中：
  - `projectile_behavior_type` 用来区分普通弹和爆炸弹。
  - `explosion_radius` 决定 AoE 检测半径。
  - `explosion_damage_multiplier` 用于控制爆炸伤害相对基础武器伤害的倍率。
  - `explosion_vfx_path` 用于后续资源化爆炸视觉。
  - `explosion_hit_limit` 作为可选扩展，限制一次爆炸最多命中的目标数。

### Phase 3：运行时实例化分流
- `WeaponInstance` 在发射投射物时，根据 `projectile_behavior_type` 选择生成：
  - 普通 `Bullet`
  - 或 `ExplosiveBullet`
- 这一步的关键目标是：
  - 不破坏现有普通枪的稳定性
  - 不要求 `Bullet.cs` 理解爆炸专属字段

### Phase 4：爆炸判定实现
- `ExplosiveBullet` 计划流程：
  1. 初始化飞行参数、伤害参数、爆炸半径。
  2. 像普通子弹一样朝目标方向飞行。
  3. 命中敌人、撞到阻挡物、或寿命结束时进入 `Explode()`。
  4. `Explode()` 执行一次性范围检测。
  5. 枚举命中的怪物，逐个走现有伤害结算。
  6. 播放爆炸视觉后回收对象。
- 范围检测第一版建议：`Physics2D.OverlapCircleAll`。
- 第一版先做圆形范围，不先上扇形、矩形或自定义贴图命中区。

### Phase 5：爆炸伤害策略
- 第一版建议：爆炸伤害 = 武器基础伤害 × `explosion_damage_multiplier`。
- 伤害结算仍走现有角色属性系统，以保证：
  - 远程伤害加成仍生效
  - 暴击规则仍统一
  - 百分比伤害加成仍统一
- 第一版默认不区分“直接命中伤害”和“爆炸伤害”两段分离。
- 推荐首版行为：命中后只爆一次，伤害来源统一视为爆炸结算，减少重复伤害与双判定问题。

### Phase 6：视觉与资源策略
- 飞行物 prefab 独立：`explosive_bullet.prefab`
- 爆炸特效优先级：
  1. 先用占位 sprite / 简易扩散效果验证逻辑
  2. 稳定后再接正式爆炸特效资源
- 视觉仍尽量数据驱动，特效路径可挂在武器配置里。
- 如果第一版资源不足，允许先只做简化的闪白、扩圈或瞬时 sprite 动画，不阻塞逻辑联调。
- 当前仓库状态下，如果武器图标、世界图、爆炸序列帧还停留在 `Assets/AI/WeaponCannon/`，运行时不会自动通过 `Resources.Load` 读到；需要后续转入 `Assets/Resources/Weapons/Icons/`、`Assets/Resources/Weapons/Sprites/`、`Assets/Resources/Weapons/Effects/`。

### Phase 7：首把样板武器落地
- 第一把样板：小火炮。
- 小火炮目标：
  - 子弹速度偏慢
  - 单发
  - 命中即爆
  - 爆炸半径明显大于普通子弹碰撞盒
- 验证通过后，再复用同一链路接入重型火炮。
- 当前状态：重型火炮已按同一链路接入，后续重点转为数值和资源表现细调，而不是继续扩行为分支。

## 为什么不继续改 `Bullet.cs`
- `Bullet.cs` 当前已经承担普通投射物的大部分共性。
- 如果再往里塞爆炸、落地 AoE、持续火焰、分裂碎片，类会很快变成条件分支堆。
- 分离后收益更明确：
  - 普通枪不会被爆炸逻辑牵连
  - 爆炸调试更直接
  - 以后要加持续区域伤害或榴弹抛物线，也有独立落点

## 第一版暂不处理的内容
- 抛物线弹道
- 爆炸后留下持续伤害区域
- 友伤
- 复杂地形遮挡
- 爆炸对可破坏物、箱子、机关的不同判定
- 子母弹、分裂弹、多层连爆

## 风险点
- 如果直接命中目标时先触发单体伤害、再触发爆炸，容易双倍结算。
- 如果对象池回收时没有重置爆炸状态，可能出现复用后不爆或重复爆炸。
- 如果范围检测层级设置不对，可能炸不到怪或把无关碰撞体也算进去。
- 如果把普通弹和爆炸弹共用同一个初始化入口但字段没有清干净，容易出现旧状态残留。

## 推荐实现顺序
1. 给武器配置补行为类型与爆炸字段。
2. 新建 `ExplosiveBullet.cs` 与 `explosive_bullet.prefab`。
3. 在 `WeaponInstance` 做投射物分流实例化。
4. 先接小火炮配置并完成最小可用联调。
5. 验证伤害、范围、回收、特效后，再扩到重型火炮。

## 当前结论
- 爆炸弹不是给 `Bullet.cs` 打补丁，而是新开独立行为链。
- 普通弹继续维护“通用直射投射物”职责。
- 小火炮是爆炸弹链的第一把样板武器。
- 后续所有新增结论，都应优先直接补写到这份设计文档，而不是只保留在聊天记录里。

## 流派 / 道具扩展原则（第一阶段）
- 流派加成只作为“轻度倾向”，不是锁牌，不应该把商店刷成只剩同流派物品。
- 继续沿用 `ShopSystem.baseWeight + archetypeBonus` 机制，只做小幅加权，不改成硬保底或强定向池。
- 流派拆成两层：
  - 基础数值层：伤害、攻速、范围、暴击、穿透数、弹射数、爆炸增幅等。
  - 命中后处理层：爆炸、闪电链、地面燃烧、吸血触发、击杀触发等。
- 第一阶段先不把所有效果做成庞大框架，优先顺着现有代码把三条主流派打通：
  - 爆炸流派
  - 近战流派
  - 子弹流派

## 现有系统可直接复用的落点
- 爆炸流派：直接复用 `ExplosiveBullet` 的命中后范围处理。
- 子弹流派：直接复用 `Bullet` 的 `piercing` / `bounce`。
- 近战流派：直接复用 `WeaponHitbox` 与 `DamageUtil` 的近战结算。
- 商店流派倾向：直接复用 `ShopSystem.GetCurrentPlayerTags()` 与 `RollOneItem()` 的标签加权。

## 第一阶段目标
- 先验证当前属性系统对战斗是否真正生效：
  - `AttackSpeed`
  - `Range`
  - `DamagePercent`
  - `MeleeDamage`
  - `RangedDamage`
- 先补齐三条流派最小可玩支撑：
  - 爆炸流派：爆炸半径、爆炸伤害倾向
  - 近战流派：近战伤害、吸血、攻速倾向
  - 子弹流派：穿透数、弹射次数、攻速倾向
- 先完成“能跑、能测、能讲原理”的版本，再决定第二阶段是否抽象成更完整的命中效果模块。

## 面试表达建议（贴当前工程）
- 可以统一表述为：
  - 武器系统分为“基础数值层”和“命中后处理层”。
  - 基础数值层负责伤害、攻速、范围、暴击。
  - 命中后处理层负责爆炸、穿透、弹射，以及未来的闪电链、地面燃烧等效果。
- 当前工程里：
  - `Bullet` 已经是普通远程命中后处理样板。
  - `ExplosiveBullet` 已经是 AoE 命中后处理样板。
  - 后续的闪电链、本地持续燃烧区域，本质上都是“命中后再派生一个额外效果模块”。

## 第一阶段资源 / 配置准备清单
- 这部分需要和实现并行推进，避免代码改好了但表和图标没跟上。
- 你需要准备：
  - `PropData.xlsx` 中第一批流派道具条目
  - 每个道具的中文名
  - 每个道具的图标
  - 每个道具的 `tags`
  - 哪些道具是纯属性加成，哪些道具后续要做特殊效果
- 第一批建议先做 9 个以内：
  - 爆炸流派 3 个
  - 近战流派 3 个
  - 子弹流派 3 个
- 第一阶段图标不用追求终版，但至少要有可区分占位图，避免商店和背包验证阶段全靠日志。

## 第一阶段建议的标签集合
- `Explosion`
- `Melee`
- `Projectile`
- `AttackSpeed`
- `Sustain`
- `Fire`

## 第一阶段建议的道具方向
- 爆炸流派：
  - 炸药包：偏爆炸半径
  - 高能装药：偏爆炸伤害
  - 余烬燃料：为后续地面燃烧预留标签
- 近战流派：
  - 磨刀石：偏近战伤害
  - 吸血护符：偏生命窃取
  - 狂战护腕：偏攻击速度
- 子弹流派：
  - 穿甲弹：偏穿透数
  - 弹射芯片：偏弹射次数
  - 高压枪机：偏攻击速度 / 远程输出

## 第一阶段实现顺序
1. 修正当前属性在战斗链路里的明显缺口（先保证负攻速、负范围这类减益也真的生效）。
2. 做一次战斗验证，确认 `AttackSpeed` / `Range` / `DamagePercent` / `MeleeDamage` / `RangedDamage` 都能观察到变化。
3. 为流派相关属性补系统入口。
4. 在 `PropData.xlsx` 中加第一批流派道具。
5. 借助现有商店标签加权做轻度流派倾向验证。
6. 第二阶段再考虑把闪电链、燃烧地面抽象成统一的命中效果模块。
