# 角色与怪物动画 Design

## 总结
土豆兄弟的角色和怪物动画，主体不是“逐帧精灵动画”，而是“单图/少量部件 + Transform 关键帧 + 少量材质闪白 + 少量粒子/特效”。

这件事对 Unity 很重要，因为正确复刻思路不是给每个怪物做一套庞大的 Animator 状态机，而是：
- 角色：身体、腿、武器分层，关键帧控制位置/旋转/缩放
- 怪物：本体 Sprite + 前摇压缩/抬升/回弹 + 受击闪白
- 特效和子弹：需要时才用序列帧或独立 Prefab

## 一、角色动画怎么做

### 1. 可选角色和玩家本体的关系
- 可选角色很多，但从当前项目资源看，主动画系统是共用玩家本体的。
- 也就是说，很多“角色”的差异更偏数据、起始武器、图标、外观附加物，不是整套动作资源完全不同。
- 所以后续 Unity 项目不该为 49 个可选角色分别重做一套基础动作。

### 2. 玩家动画主结构
推荐 Unity 层级：

```text
PlayerRoot
- AnimationRoot
  - Shadow
  - Highlight
  - BodySprite
  - LegsRoot
    - LegL
    - LegR
- WeaponsRoot
- FXRoot
```

### 3. 玩家主动画类型
- `idle`：呼吸感，上下轻微浮动，整体缩放有轻微压缩/回弹。
- `move`：身体弹跳，左右腿局部旋转/位移，武器根节点轻微跟随晃动。
- `landing`：从空中落地，配合降落伞场景。
- `won/dance`：庆祝动作，身体和腿有更大幅度摆动。
- `hurt`：不是单独动作，而是材质闪白 + 无敌帧。

### 4. 玩家不是序列帧主导
- 身体不是逐帧走路贴图。
- 腿是单独部件，不是整张人物序列帧。
- 真正变化的是节点属性：`position / rotation / scale / modulate`。

### 5. Unity 实现建议
- 如果项目已有 Animator，可以让 Animator 驱动 `idle/move/landing/win` 这些状态。
- 但每个状态内的动画内容应该是部件关键帧，不是切换多张身体图片。
- 如果项目不想堆 Animator，也可以用 DOTween / 自写曲线驱动。

### 6. 受击怎么做
- 不建议额外做复杂的 hurt clip。
- 直接做：
```text
材质闪白 0.05s - 0.12s
可选轻微缩放抖动
无敌帧计时
受击音
```

## 二、怪物动画怎么做

### 1. 主流方案
怪物的主流实现是：
- 单张怪物图
- 一个 `Animation` 容器
- 一个 `Sprite2D`
- 通过 `AnimationPlayer` 在攻击前播放前摇
- 动画里改 `position / scale / self_modulate`

### 2. 不是逐帧怪物
- 当前扫描结果里，怪物主系统没有发现普遍使用 `AnimatedSprite2D/SpriteFrames`。
- 所以 Unity 复刻时，默认不该先找怪物序列帧。

### 3. 怪物主要动画模式

#### A. 普通追踪怪
- 平时移动主要靠寻路/位移，视觉上可以只做轻微弹跳。
- 攻击或冲锋前做压缩、回弹或变红提示。

#### B. 远程怪
- 攻击前摇：身体上抬或压缩。
- 前摇时 `self_modulate` 偏红。
- 关键帧到达时发射 projectile。
- 然后回到 idle。

#### C. 冲锋怪
- 前摇动画比远程怪更明显。
- 身体后拉或压缩。
- 关键帧触发 charge。
- 冲出后回到默认状态。

#### D. 特殊/大体型怪
- 可能多一个旋转支点、成长缩放、外围部件或召唤物。
- 但核心思路依旧不是大段逐帧，而是节点属性动画。

### 4. Unity 推荐层级

```text
EnemyRoot
- AnimationRoot
  - Shadow 可选
  - BodySprite
  - ExtraPivot 可选
  - ExtraParts 可选
- HitFlashController
- AttackController
```

### 5. Unity 推荐实现
- 平时：
  - 朝向用 `flipX` 或 `localScale.x`。
  - 轻微上下浮动可选。
- 攻击前摇：
  - `AnimationRoot.localPosition`
  - `AnimationRoot.localScale`
  - `BodySprite.color`
- 攻击触发：
  - 在动画事件点或时间点生成 projectile / 开启 charge / 生成召唤物。
- 受击：
  - 材质闪白

## 三、什么时候用序列帧

### 适合用序列帧的内容
- 子弹本身有多帧图
- 火焰、爆炸、斩击轨迹、枪口火焰
- 特殊投射物或能量球

### 不适合默认用序列帧的内容
- 玩家本体走路
- 绝大多数怪物本体动作
- 普通近战和远程攻击的主动作

结论：
- 角色/怪物本体以 Transform 动画为主
- 特效/投射物才更适合序列帧

## 四、给另一个 Unity 项目的执行要求
- 请以你自己的 Unity 项目为基础实现，不要强行照搬 Godot 结构名。
- 如果已有 Animator、Tween、材质闪白、对象池、Projectile 系统，优先接入已有系统。
- 必须实现的重点是功能和观感：
  - 玩家如何 idle/move/landing
  - 怪物如何前摇、攻击、回弹
  - 受击如何闪白
  - 哪些对象需要序列帧，哪些只需要缩放/位移

## 五、最小落地顺序
1. 先做玩家 `idle + move + hurt flash`。
2. 再做玩家 `landing` 和可选 `dance/win`。
3. 做一只普通近战怪：移动 + 前摇压缩 + 受击闪白。
4. 做一只远程怪：前摇 + 发射子弹 + 受击闪白。
5. 再补充大体型怪、旋转部件怪、成长型怪。

## 六、一句话结论
土豆兄弟的角色和怪物动画，主方案是“关键帧驱动节点属性”，不是“所有东西都用序列帧”。你应该把精力放在分层、前摇、回弹、闪白和事件触发上，而不是先去找一堆不存在的走路帧。
